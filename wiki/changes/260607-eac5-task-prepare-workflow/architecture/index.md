# Task Prepare Workflow Architecture

## Decision Summary

- Add a new top-level CLI command group: `weave task`.
- Add `weave task prepare` as the deterministic branch-readiness command.
- Add a new agent skill and slash command: `/weave-prepare`.
- Keep prepare strictly local and branch-readiness-only; no implementation, task status updates, commit, push, PR, stash, discard, or remote branch behavior.
- Use `tasks.md` as the source of task-to-repo mapping.
- Use top-level `status.yml.branch` as the canonical desired branch.
- Store per-repo readiness under `status.yml.execution.repos`.
- In repo mode, prepare validates the artifact root and records root readiness.
- In workspace mode, prepare validates artifact-root branch alignment, then prepares selected registered implementation repos.
- Use a two-phase preflight/apply flow so obvious blockers are found before any selected repo branch is moved.
- Block on detached HEAD or unknown current branch for git repos.

## Architecture Overview

The prepare workflow has two layers:

- CLI layer: `weave task prepare` performs deterministic parsing, repo derivation, git preflight, branch preparation, and `status.yml` updates.
- Skill layer: `/weave-prepare` handles agent UX, no-argument prompting, argument interpretation, CLI invocation, and human-readable summaries.

The CLI owns all durable state mutation. The skill should not hand-edit `status.yml` or perform branch movement directly.

## CLI Command Design

Register a new command group in `src/cli.ts`:

```ts
program.addCommand(taskCommand());
```

The command surface should be:

```bash
weave task prepare T1 T3
weave task prepare --scope backend
weave task prepare --all
weave task prepare --json
```

Validation rules:

- Exactly one selector mode must be provided.
- Explicit task ids cannot be combined with `--scope` or `--all`.
- `--scope` cannot be combined with `--all`.
- No selector should fail with a helpful message that lists valid forms.
- JSON output should include selected tasks, selected repos, per-repo actions, skipped non-git folders, and blockers.

The CLI should not implement the no-argument prompt. The no-argument prompt belongs to `/weave-prepare`; the CLI should be deterministic and script-friendly.

## Task Parser

Implement task parsing in `src/lib/tasks.ts`.

Parse `tasks.md` detail sections instead of relying only on the active task index table. The detail sections are the canonical metadata blocks and are less vulnerable to table formatting changes.

Minimum parsed shape:

```ts
export type ParsedTask = {
  id: string;
  title: string;
  status?: string;
  type?: string;
  scope?: string;
  primaryRepo?: string;
  repos: string[];
};
```

Parsing rules:

- Recognize sections shaped as `## T#: <title>`.
- Ignore `QF#` and `R#` sections for prepare v1.
- Parse metadata lines such as `Status:`, `Type:`, `Scope:`, `Primary repo:`, and `Repos:`.
- Treat comma-separated `Repos:` values as multiple repo ids.
- Treat `Repos: None`, blank values, and equivalent placeholders as no repos.
- Preserve original scope labels in output while matching scopes case-insensitively.

Selection rules:

- Explicit task selection returns exactly the requested `T#` tasks or fails if any requested id is missing.
- Scope selection returns all `T#` tasks whose `Scope` matches case-insensitively.
- All selection returns all parsed `T#` tasks.
- Selection is status-agnostic.

## Repo Derivation

For each selected task, derive repo ids from:

```text
Primary repo
Repos
```

Derivation rules:

- Use the union of `Primary repo` and `Repos`.
- De-duplicate while preserving stable order by first occurrence.
- Ignore `None`, empty values, and `workspace` only when they do not denote a concrete implementation repo.
- In repo mode, missing or ambiguous repo metadata maps to a synthetic root target.
- In workspace mode, missing or ambiguous repo metadata is a blocker because Weave cannot safely decide which sub-repo branches to prepare.
- Do not derive repo ids from `Repo Involvement` in v1; that section remains guidance.

## Active Change And Mode Resolution

`task-prepare` should resolve the active change through the same cwd-dispatched model used by existing change commands.

Recommended helper output:

```ts
type ActiveChangeContext = {
  target: { id?: string; name?: string; path: string };
  change: {
    id: string;
    path: string;
    changePath: string;
    branch: string;
  };
  mode: "repo" | "workspace";
};
```

Use `findWorkspaceMode` / `resolveChangeContext` to determine whether the artifact root is repo mode or workspace mode.

## Branch Preflight And Apply Flow

Use a two-phase algorithm.

### Phase 1: Preflight

For the artifact root:

- If it is not a git repo, continue and report that branch alignment could not be checked.
- If it is a git repo and current branch is unknown or detached, block.
- If current branch differs from `status.yml.branch`, block.
- If current branch matches `status.yml.branch`, continue.

For each selected implementation repo:

- Resolve the absolute path.
- If the path is missing, block.
- If the target is not a git repo, plan `skipped_not_git`.
- If it is a git repo and current branch is unknown or detached, block.
- Read dirty state live with `git status --porcelain`.
- If current branch is expected branch, plan `already_active` even when dirty.
- If current branch differs and repo is dirty, block.
- If expected branch exists and repo is clean, plan `checked_out`.
- If expected branch is missing and repo is clean, plan `created` from current branch.

If any blocker exists, return without applying branch changes to any selected repo.

### Phase 2: Apply

For each preflight plan:

- `already_active`: no branch movement.
- `checked_out`: `git checkout <branch>`.
- `created`: `git checkout -b <branch>` from the repo's current clean branch.
- `skipped_not_git`: no git action.

After each successful plan, collect the current HEAD if git and write readiness into `status.yml.execution.repos`.

## Git Helper Additions

Extend `src/lib/git.ts` with reusable helpers:

```ts
export async function currentBranch(cwd: string): Promise<string | undefined>;
export async function isWorktreeDirty(cwd: string): Promise<boolean>;
export async function branchExists(cwd: string, branch: string): Promise<boolean>;
export async function checkoutBranch(cwd: string, branch: string): Promise<void>;
export async function createBranch(cwd: string, branch: string): Promise<void>;
export async function currentHead(cwd: string): Promise<string | undefined>;
```

Use non-interactive `git` invocations only. Do not add helpers for stash, commit, push, or PR behavior in this change.

Detached HEAD can be detected when `git branch --show-current` returns empty while `findGitRoot` succeeds. Treat that as a blocker.

## Status Storage Writer

Read and write `status.yml` with `yaml`, preserving existing top-level fields by spreading the parsed object and replacing only `execution` and `updated_at` as needed.

Storage shape:

```yaml
execution:
  version: 1
  branch: change/<change-id>
  repos:
    <repo-id>:
      path: <relative path or .>
      mode: <repo | workspace>
      branch: change/<change-id>
      state: <prepared | skipped>
      branch_status: <created | checked_out | already_active | skipped_not_git>
      prepared_head: <git sha, omitted when not git>
      prepared_at: <iso timestamp>
      verified_at: <iso timestamp>
```

Update rules:

- Top-level `status.yml.branch` is canonical.
- Set `execution.branch` to top-level `branch` on successful prepare.
- If existing `execution.branch` differs from top-level `branch`, treat prior repo readiness as stale for decision-making.
- Preserve existing `execution.repos` entries that are not selected in this run when `execution.branch` matches the current branch.
- For a selected repo already recorded for the same branch, preserve `prepared_at` and update `verified_at`.
- For a selected repo newly prepared for this branch, set both `prepared_at` and `verified_at` to the current time.
- Do not store dirty state.
- Do not store `last_prepare`.
- Do not store selector-specific `preparations`.

For non-git selected repos:

```yaml
state: skipped
branch_status: skipped_not_git
```

Do not include `prepared_head` for non-git entries.

## JSON Result Shape

Return enough data for `/weave-prepare` and future execution preflight to summarize without reparsing text.

Recommended shape:

```ts
type PrepareResult = {
  status: "ok" | "blocked";
  change: { id: string; branch: string; path: string };
  selector: { type: "tasks" | "scope" | "all"; values?: string[]; value?: string };
  mode: "repo" | "workspace";
  tasks: Array<{ id: string; title: string; scope?: string }>;
  repos: Array<{
    id: string;
    path: string;
    mode: "repo" | "workspace";
    state: "prepared" | "skipped";
    branch_status: "created" | "checked_out" | "already_active" | "skipped_not_git";
    branch: string;
    prepared_head?: string;
  }>;
  blockers: Array<{ target: string; reason: string }>;
};
```

If blockers exist, do not mutate selected repo branches and return `status: "blocked"` with non-zero CLI exit unless existing command conventions prefer throwing `ChangeCommandError`.

## `/weave-prepare` Skill

Add `templates/skills/weave-prepare/SKILL.md`.

The skill should:

- Resolve active context with Tier 1 commands.
- Read `tasks.md` when needed to suggest no-argument choices.
- Map `all` to `weave task prepare --all --json`.
- Map task id arguments such as `T1 T3` to `weave task prepare T1 T3 --json`.
- Map other single free-form arguments to `weave task prepare --scope <value> --json`.
- Ask the user when no argument is supplied.
- Summarize prepared, skipped, and blocked repos.
- Explicitly state that prepare does not implement, commit, push, or open PRs.

Add `templates/opencode/commands/weave-prepare.md`:

```md
---
description: Prepare task execution branches for a Weave change
---

Load and follow the `weave-prepare` skill.

Context: $ARGUMENTS
```

The existing `src/lib/agent-skills.ts` installer will pick up new default skill folders and opencode command templates through directory scanning.

## Interaction With Existing Change Commands

Do not modify `weave change new` or `weave change switch` to prepare workspace sub-repos. Those commands should continue to manage only the resolved artifact root.

`weave task prepare` is the explicit bridge from tasks to implementation repo branches.

This separation keeps lifecycle context switching independent from implementation readiness.

## Risks And Mitigations

- Risk: Partial branch movement if one repo succeeds and a later repo blocks. Mitigation: two-phase preflight before applying any branch action.
- Risk: Agents infer execution readiness from stale `status.yml.execution`. Mitigation: prepare always rechecks live git and future execution should also recheck live git.
- Risk: Detached HEAD branches are accidentally used as bases. Mitigation: block detached or unknown branch states.
- Risk: Workspace mode missing repo metadata causes wrong branch prep. Mitigation: block and ask rather than guessing.
- Risk: Status metadata grows stale when tasks change. Mitigation: `status.yml.execution.repos` records branch readiness, not task selection; task selection remains derived from `tasks.md`.
- Risk: Existing changes lack repo metadata. Mitigation: repo mode defaults to root; workspace mode asks users to clarify or regenerate tasks.

## Test Plan

Add unit and integration tests for:

- Parsing `T#` detail sections from realistic `tasks.md`.
- Multiple explicit task ids.
- Case-insensitive scope selection.
- `--all` selecting all `T#` tasks regardless of status.
- Repo mode defaulting missing repo metadata to root.
- Workspace mode blocking missing repo metadata.
- Workspace mode blocking unknown registered repo ids.
- Artifact-root branch mismatch blocking.
- Detached HEAD / unknown branch blocking for git repos.
- Dirty repo already on expected branch succeeding.
- Dirty repo on another branch blocking before any selected repo branch action.
- Clean repo with existing branch checking out the expected branch.
- Clean repo with missing branch creating from the current branch.
- Non-git selected repo recording `state: skipped` and `branch_status: skipped_not_git`.
- `execution.repos` preserving records from prior selectors.
- `execution.branch` mismatch causing current-branch readiness refresh.
- `weave-prepare` skill and opencode command packaging.
