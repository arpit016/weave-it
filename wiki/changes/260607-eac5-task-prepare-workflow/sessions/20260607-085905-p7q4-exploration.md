# Session Capture: Exploration - 2026-06-07

## Summary

Captured the product exploration for a new Weave task preparation workflow. The discussion started from the workspace-aware task metadata problem: `tasks.md` can identify relevant repos, but workspace sub-repos still need their own local change branches before implementation starts. The user clarified that this should become a separate new change focused on preparation, not execution.

## Decisions Made

- Create a new change for task preparation instead of extending the completed workspace-aware issues change.
- Use `prepare` as the product term.
- Expose prepare through `/weave-prepare` and `weave task prepare`.
- Keep prepare local-only and branch-readiness-only.
- Exclude task execution, verification, task status updates, commits, pushes, PRs, remote branch creation, stash, discard, and worktree movement from this change.
- Support task id, multiple task id, scope, and all selection.
- Ask the user when `/weave-prepare` has no arguments and suggest scopes, task ids, and `all`.
- Treat prepare as task-status agnostic.
- Match scope labels case-insensitively.
- In workspace mode, derive repos from selected tasks and stop on missing or ambiguous repo metadata.
- In repo mode, default missing or ambiguous repo metadata to the repo root.
- Define `all` as all repos referenced by all `T#` tasks, not all registered workspace repos.
- Require artifact-root branch alignment with top-level `status.yml.branch`.
- Create missing sub-repo branches from the repo's current clean branch.
- Check out existing sub-repo change branches when the repo is clean.
- Allow dirty repos already on the expected branch.
- Stop before switching dirty repos that are not on the expected branch.
- Record non-git selected repos/folders as `skipped_not_git` and treat prepare as succeeded.
- Store per-repo readiness in `status.yml.execution.repos`.
- Store `state: prepared`, `prepared_at`, and `verified_at` for prepared repos.
- Do not store dirty state, `last_prepare`, or selector-specific preparation records in v1.
- Preserve existing `execution.repos` records across different prepare selections.
- Treat `execution.branch != status.yml.branch` as stale readiness.

## Options Considered

- Store involved repos in `status.yml` during task generation.
- Derive involved repos from `tasks.md` during prepare.
- Track selector-specific preparation records.
- Track only per-repo readiness.
- Store dirty worktree state.
- Keep dirty state as live-only output.
- Make `/weave-prepare all` mean all registered repos.
- Make `/weave-prepare all` mean all task-referenced repos.
- Fail on non-git selected repos.
- Record non-git selected repos as skipped.

## Rejected Approaches

- Static `involved_repos` in `status.yml` during task generation was rejected because it duplicates `tasks.md` and can go stale.
- Selector-specific `execution.preparations` were rejected for v1 because per-repo readiness is enough for the branch-readiness problem.
- `execution.last_prepare` was rejected for v1 because it is not needed for correctness.
- Persisting dirty state was rejected because dirty state is volatile and should be checked live.
- Preparing all registered workspace repos for `all` was rejected because it mutates unrelated repos.
- Auto-stashing, auto-committing, discarding, pushing, and PR creation were rejected as unsafe or out of scope.

## User Preferences

- Keep the workflow simple and practical.
- Separate prepare from execute.
- Build execute as a future separate change.
- Treat prepare as branch readiness only.
- Avoid over-modeling selector history.
- Prefer per-repo readiness records in `status.yml`.
- Preserve existing readiness records across consecutive prepares.

## Agent Recommendations

- Create a detailed PRD for the new task prepare change.
- Keep current-state truth in `tasks.md` and branch-readiness state in `status.yml.execution.repos`.
- Add `/weave-prepare` as a skill wrapper over deterministic CLI behavior.
- Implement repo mode as validation and workspace mode as implementation-repo branch preparation.
