# Session Capture: Architecture - 2026-06-07

## Summary

Captured the architecture design for the task prepare workflow. The design adds a deterministic `weave task prepare` CLI, a `/weave-prepare` skill wrapper, task parsing from `tasks.md`, repo derivation from task metadata, a two-phase preflight/apply branch-readiness algorithm, and per-repo readiness storage under `status.yml.execution.repos`.

## Decisions Made

- Add `src/commands/task.ts` for the `weave task` command group.
- Add `src/lib/tasks.ts` for `tasks.md` parsing and selector resolution.
- Add `src/lib/task-prepare.ts` for active-change resolution, repo derivation, branch preflight/apply, and status storage.
- Extend `src/lib/git.ts` with reusable branch/current/dirty/head helpers.
- Prefer exporting a small active-change context helper from `src/lib/changes.ts` over duplicating private current-change logic.
- Parse task detail sections rather than relying only on the active task index table.
- Use a two-phase preflight/apply algorithm so one repo blocker prevents all branch movement.
- Block on detached HEAD or unknown branch state for git repos.
- Keep non-git selected repos as successful `skipped_not_git` entries.
- Keep `weave change new` and `weave change switch` scoped to the artifact root; do not make them prepare implementation repos.
- Add `templates/skills/weave-prepare/SKILL.md` and `templates/opencode/commands/weave-prepare.md`.

## Options Considered

- Reusing only `src/lib/changes.ts` for branch prep.
- Creating dedicated task parsing and task prepare libraries.
- Applying branch actions as repos are discovered.
- Preflighting all repos before any branch action.
- Allowing clean detached HEAD repos as branch bases.
- Blocking detached HEAD or unknown branch states.

## Rejected Approaches

- Duplicating current-change resolution inside task prepare was rejected because it risks divergence from existing change command behavior.
- Table-only task parsing was rejected because detail metadata is more canonical and less formatting-sensitive.
- Single-pass branch mutation was rejected because it can leave some repos moved before a later blocker is discovered.
- Allowing detached HEAD as a base was rejected because it can create change branches from accidental commits and weakens branch-readiness clarity.

## User Preferences

- Keep prepare separate from execution.
- Keep prepare local-only and safe.
- Avoid over-modeling selector history.
- Block on detached HEAD or unknown current branch for git repos.

## Agent Recommendations

- Use `architecture/index.md` as the only architecture artifact for this change.
- Generate tasks only after this architecture is reviewed and captured.
- Keep tests broad enough to cover repo mode, workspace mode, branch safety, storage preservation, and skill packaging.

## Unresolved Points

- Future execution, publish, PR creation, remote branch creation, and worktree mode are explicitly out of scope.
