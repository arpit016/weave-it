# Session Capture: Architecture - 2026-06-07

## Summary

The architecture discussion refined how to implement two command UX changes without coupling them unnecessarily:

- `weave workspace` should compute local repo availability at display time and expose it as `availability: "present" | "missing"` for workspace-mode `repos[]`.
- Weave skills should replace the old verbatim notice-surfacing rule with a silent command output policy and a concrete notice message matrix.

The implementation should keep persisted workspace metadata pure, keep existing task-prepare missing repo blockers unchanged, and update skill templates plus installed skill copies consistently.

## Decisions Made

- Compute repo availability in `src/lib/show-workspace.ts`, not in `src/lib/workspace-repos.ts`.
- Do not persist availability in `.weave/workspace.yml`; it is local runtime state.
- Add `availability` only to workspace-mode `repos[]`; repo-mode `folders[]` remains unchanged.
- Use `pathExists(path.join(workspacePath, repo.path))` to derive `present` or `missing`.
- Do not call `realpath` for registered repo paths when computing availability, because missing paths are expected.
- Leave `src/lib/task-prepare.ts` missing-repo blockers unchanged.
- Replace the shared `# Surface Weave Notices` boilerplate with a silent command output policy.
- Update `src/lib/skill-template-checks.ts` and `tests/agent-skills.test.ts` so the new policy is asserted centrally.
- Include concrete notice wording in shared skill guidance so skills do not invent or relay raw notice text.

## Options Considered

- Persisting `availability` in workspace metadata was rejected because availability is local and changes per checkout.
- Computing availability in `workspace-repos.ts` was rejected because that module owns metadata parsing and registration, not runtime display state.
- Treating all notices as hidden was rejected; package outdated, relevant skill outdated, and relevant skill modified should still surface when actionable.
- Surfacing raw notice messages was rejected because the current notice text is diagnostic, not user-friendly skill response copy.

## Rejected Approaches

- Do not auto-clone or hydrate missing repos from `weave workspace`.
- Do not infer repos from `.gitignore`.
- Do not add repo availability to repo-mode session folder output in this change.
- Do not remove command blocks from skills; only change how command output is handled.
- Do not show `Notices: ...`, raw `notices[].message`, full notice JSON, or full skill lists unless the user asks for diagnostics.

## User Preferences

- Package version notices should be simple: show only when Weave is actually outdated; otherwise show nothing.
- The outdated-package user message should be concise and actionable.
- Skill command output should be invisible unless it changes what the user needs to know or do.
- If a notice is shown, the message should be normal user-facing copy, not copied directly from the CLI notice payload.

## Agent Recommendations

- Add a `RepoAvailability` union and `availability` field to `ShowWorkspaceRepo`.
- Build workspace-mode repos through an async helper in `show-workspace.ts` that augments metadata rows with availability.
- Update workspace tests to cover both present and missing registered repos.
- Rename `EXPECTED_NOTICE_BOILERPLATE` to a silent-output constant such as `EXPECTED_SILENT_COMMAND_OUTPUT`.
- Replace every `# Surface Weave Notices` section in `templates/skills`, `.agents/skills`, and `.claude/skills`.
- Add negative tests ensuring no bundled skill still contains `# Surface Weave Notices` or `surface them to the user verbatim`.
