# Session Capture: Exploration - 2026-06-07

## Summary

The discussion clarified two related command UX expectations for Weave:

- Workspace metadata can list repos that are not present in a new engineer's local checkout because repo folders are gitignored in the outer workspace repo.
- Weave skill instructions should treat CLI calls as internal context-loading or lifecycle operations and should not show raw command output to the user.

The user wants the command and skill experience to be quieter and more helpful: surface only facts that matter for the current work, especially missing repos when they affect context, blockers, failures, or required user action.

## Decisions Made

- `.weave/workspace.yml` remains the committed source of truth for registered workspace repos.
- Gitignored sub-repo folders are not automatically cloned or pulled just because they are listed in `.weave/workspace.yml` or `.gitignore`.
- `weave workspace` should lightly indicate when registered repos are missing locally so agents can understand available context.
- Missing repo information should be used as context, not as an automatic hydration trigger.
- Skills should run Weave CLI commands silently by default.
- Skills should not show raw stdout, JSON payloads, command echoes, internal artifact/session-state writes, or notice text verbatim.
- Tier 1 notices are not user-friendly when surfaced verbatim. Skills should treat notices as internal diagnostics and mention only user-actionable or user-relevant items in normal language.

## Options Considered

- Auto-cloning every registered repo for a new engineer was considered and rejected as too aggressive.
- A future `weave hydrate` command was identified as possible new work, but it is not currently implemented.
- Showing raw `weave workspace --json`, `weave change current --json`, `weave change status --json`, and `weave artifact current set ... --json` output was rejected as noisy.
- Keeping Tier 1 notices verbatim was rejected in favor of classifying and summarizing user-relevant notifications.

## Rejected Approaches

- Do not treat `.gitignore` as the source of truth for repos.
- Do not clone or pull missing repos automatically during workspace discovery.
- Do not make users see internal command outputs just because a skill needed context.
- Do not show notice payloads verbatim near the start of every skill response.

## User Preferences

- The user prefers concise, synthesized skill responses.
- Internal command usage should be invisible unless something needs attention.
- Missing repos should be called out lightly so exploration and architecture work can explain context limits.
- If a missing repo may matter, the skill should tell the user to add or clone it for their own context.

## Agent Recommendations

- Update all Weave skills in `templates/skills`, `.agents/skills`, and `.claude/skills` with a shared silent command output policy.
- Replace `# Surface Weave Notices` sections with a user-relevance policy for CLI notices.
- Teach `weave workspace` output or consuming skills to distinguish present and missing registered repos.
- Preserve explicit blocker/failure summaries for cases like missing repo paths during `weave task prepare`.

## Unresolved Points

- Whether to implement a dedicated `weave hydrate` command later remains undecided.
- The exact CLI shape for repo presence in `weave workspace` still needs design during implementation.
- The exact wording of the shared skill policy should be finalized while editing the skill templates.
