# Session Capture: Architecture - 2026-06-04

## Summary

Captured the engineering design for mode-aware `weave add` and `weave workspace`, synthesized from the approved Cursor plan, PRD, exploration decisions, and codebase review. Implementation has not started yet (no `src/lib/workspace-mode.ts` or `architecture.md` prior to this capture).

## Decisions Made

- Shared `findWorkspaceMode(startPath)` walks up to `.weave/workspace.yml` and reads `mode`; used by both `weave add` and `weave workspace`. Committed-truth-driven, not session-driven.
- Workspace-mode `weave add` writes only to `workspace.yml.repos` and `.gitignore`; does not write `session.folders` for sub-repos.
- Repo-mode `weave add` unchanged (session-only).
- `registerRepoIntoWorkspace` is the single write path for gitignore + workspace.yml.repos; init refactored to use it for adopted repos.
- `weave workspace` reads `workspace.yml.repos` per workspace-mode session folder; additive JSON `repos` field; graceful degradation on missing/malformed workspace.yml.
- Open technical questions resolved with defaults: precise gitignore paths, basename slug with collision error, five URL schemes.

## Options Considered

- Reading B (dual registry writes on add) vs Reading A (workspace.yml only) + show-workspace enhancement. Chose Reading A per user confirmation.
- Separate `weave repos` command vs extending `weave workspace`. Chose extend `weave workspace`.
- yaml Document API for comment preservation vs parse+stringify. Chose parse+stringify for consistency with changes.ts.

## Rejected Approaches

- Pre-populating session.folders from workspace.yml.repos at session creation.
- New `weave workspace add` subcommand.
- Mode detection from session.folders kind alone.

## User Preferences

- Minimum disruption: repo mode behavior byte-identical where possible.
- Symmetric mode awareness on `weave add` and `weave workspace`.
- Bundle `weave workspace` observability with the add feature in one change.
