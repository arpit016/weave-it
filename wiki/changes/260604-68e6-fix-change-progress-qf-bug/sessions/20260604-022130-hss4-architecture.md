# Session Capture: Architecture - 2026-06-04

## Summary

Diagnosed two CLI defects and produced a fix strategy.

1. `weave change progress` crashes on every invocation with `raw.trim is not a function`. Root cause is a Commander flag collision in `src/commands/change.ts`: `--no-invalidate` and `--invalidate <lanes>` both map to the same `invalidate` attribute, so the negatable flag defaults `options.invalidate` to boolean `true` and `parseInvalidateList(true)` calls `.trim()` on a boolean.
2. `weave change new --type <non-feat>` still scaffolds `exploration.md` and starts at `stage: exploration`. The bug-fix PRD (`260602-of9s`) already decided non-feature changes should create only `status.yml` + `sessions/` and start at `stage: started`, but that scaffolding work was never implemented (the of9s change shipped only the `tasks.md` QA-findings/refactors work).

## Decisions Made

- Fix Bug 1 entirely within `src/commands/change.ts` by reading both `noInvalidate` and `invalidateOnly` from the single Commander `invalidate` attribute (`false` => suppress, string => subset, `true`/default => pessimistic). Public flag names `--no-invalidate` and `--invalidate <lanes>` are preserved, so no skill/doc rename is needed.
- Fix Bug 2 by introducing `started` as a stored stage that is NOT an artifact lane (`changeStages` stays the four lanes). `createChange` writes `exploration.md` only for `type === "feat"`; `statusTemplate` sets `stage` to `started` for non-feature types and `exploration` for `feat`.

## Options Considered

- Bug 1: rename the public `--invalidate <lanes>` flag to `--invalidate-only` to avoid the collision. Rejected because it would ripple into multiple skill templates and docs; reading from the merged `invalidate` attribute is a smaller, contract-preserving fix.
- Bug 2: skip `exploration.md` but leave `stage: exploration`. Rejected as inconsistent (a stage with no backing artifact); the PRD explicitly specifies `stage: started`.

## Rejected Approaches

- Adding `started` to `changeStages` (the artifact-lane list). Rejected: `started` is explicitly a non-lane stage per the of9s PRD ("should not treat `started` as an artifact lane"). It must be representable in `status.yml.stage` without becoming a progressable lane.

## User Preferences

- Skip the discovery questionnaire; identify and debug both issues directly.
- Use the existing local CLI via `npm run dev --` (the `weave` global is not installed in this environment).

## Agent Recommendations

- Keep `changeStages` unchanged; add a separate `StoredChangeStage = "started" | ChangeStage` type plus an `isStoredChangeStage` guard, widen the `stage` field on the metadata interfaces, and let `readChangeMetadata`/`maxStage`/`stageIndex` tolerate `started` (index -1 so any real lane wins on progress).
- Update `templates/skills/weave-new/SKILL.md` ("Treat `exploration.md` as the first artifact") to be feature-specific and propagate byte-identical copies to `.agents/`, `.claude/`, `.opencode/`.
- Add a `tests/changes.test.ts` case for `--type fix` (no `exploration.md`, `stage: started`); existing feat cases stay valid.

## Unresolved Points

- Whether any status/`weave-next` display text needs explicit `started` handling beyond printing the stage value (current formatting just prints `change.stage`, so widening the type is expected to suffice).
- Confirm Commander v14 merges `--no-invalidate` + `--invalidate <lanes>` onto one attribute as assumed (behavior matches the observed crash; to be re-verified during implementation).
