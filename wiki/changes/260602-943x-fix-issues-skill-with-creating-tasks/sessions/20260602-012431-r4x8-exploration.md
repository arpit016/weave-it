# Session Capture: Exploration - 2026-06-02

## Summary

Promoted pending exploration session context into the live exploration artifact for the `weave-issues` local `tasks.md` change.

The promoted context covers local-only `tasks.md` generation and reconciliation, source-aware inputs, invalid task handling, testing behavior for repos with or without automated test suites, and the ownership boundary for `not_tested`.

## Decisions Made

- `weave-issues` should write local `tasks.md` after approval instead of publishing external tracker issues.
- `tasks.md` remains canonical for local issue/task breakdowns; `issues.md` should not be introduced.
- External issue references can be source context, but `weave-issues` should not mutate external trackers.
- Task generation may use any sufficiently concrete plan or context.
- Existing `tasks.md` should be reconciled on rerun, preserving progress where task intent still maps cleanly.
- Obsolete tasks should be marked `invalid` and separated from the active task index.
- Missing automated tests should not block task generation.
- Existing test infrastructure should be detected and used when present.
- Without usable test infrastructure, generated tasks should include manual or smoke verification expectations.
- `not_tested` is status vocabulary for implementers to apply after execution, not a status `weave-issues` assigns to new tasks.

## Options Considered

- Rename `tasks.md` to `issues.md`.
- Keep tracker publishing as an optional output.
- Require architecture as the only valid source for tasks.
- Delete obsolete tasks during reconciliation.
- Always create a test-harness setup task when no suite exists.
- Require strict TDD wording.
- Generate tasks as `not_tested` when the repo lacks automated tests.

## Rejected Approaches

- `issues.md` was rejected because existing Weave lifecycle and prior decisions already use `tasks.md` as local issue evidence.
- External tracker publishing was rejected for this change to keep outputs local-only.
- Architecture-only task generation was rejected because issue breakdown should work from any solid plan.
- Deleting obsolete tasks was rejected because preserving invalidated history is useful.
- Mandatory test setup was rejected because it can expand scope when the source plan did not ask for it.
- Strict TDD was rejected in favor of vertical-slice completeness.
- Assigning `not_tested` during generation was rejected because verification status is only known during implementation.

## User Preferences

- Prefer local `tasks.md` tracking.
- Prefer source-aware task generation and lifecycle progress.
- Prefer preview-and-approval before `tasks.md` writes.
- Prefer preserving progress during reconciliation.
- Prefer `invalid` for obsolete tasks.
- Prefer vertical-slice completeness over strict TDD process language.
- Prefer automated test expectations when a usable test base exists.
- Prefer manual or smoke verification fallback when no usable test base exists.
- Prefer `not_tested` as implementer-applied tracking vocabulary.
