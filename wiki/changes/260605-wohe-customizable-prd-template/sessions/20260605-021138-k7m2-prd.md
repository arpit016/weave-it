# Session Capture: PRD - 2026-06-05

## Summary

The user wants the default PRD document template to live outside the `weave-prd` skill instructions so users can modify the template for their own needs. The discussion explored the current inline template in `templates/skills/weave-prd/SKILL.md`, the existing skill installation model, and the plan for making the PRD template a user-editable supporting file.

## Decisions Made

- Treat this as a new Weave change rather than folding it into the workspace-aware skills change.
- Capture the work in the PRD lane.
- Keep scope focused on `weave-prd` for now.
- Move the PRD structure out of `SKILL.md` into a sibling template file in the `weave-prd` skill folder.
- Prefer a skill-folder supporting file because it matches agent skill conventions and can reuse the existing install, update, reset, diff, and manifest behavior.

## Options Considered

- Store the template as `templates/skills/weave-prd/prd-template.md`, installed beside `SKILL.md` for each agent.
- Store a single shared template in `wiki/templates/prd.md`.
- Store a single managed template under `.weave/templates/prd.md`.
- Extend the same extraction to `weave-architect` and `weave-knowledge`.

## Rejected Approaches

- Do not leave the PRD template embedded in `SKILL.md`; that makes customization require editing the skill instructions themselves.
- Do not broaden the change to every embedded template immediately; the user specifically asked about the PRD template.

## User Preferences

- The PRD template should be separate from the PRD skill so users can modify it as needed.
- The change should be captured as its own change and added to the PRD lane.

## Agent Recommendations

- Add `templates/skills/weave-prd/prd-template.md` as the canonical bundled PRD template.
- Update `templates/skills/weave-prd/SKILL.md` to instruct agents to read the sibling `prd-template.md` and follow user modifications.
- Extend `src/lib/agent-skills.ts` so non-`SKILL.md` files in a skill folder are installed and managed as resources.
- Track resources independently in `.weave/agents.yml` so user edits to `prd-template.md` are preserved by update/install and only reset when explicitly requested.
- Add focused tests in `tests/agent-skills.test.ts` for installing, preserving modified, diffing, and resetting the new template resource.

## Unresolved Points

- Whether the resource manifest should use a new `resources` bucket or represent the template under the existing `skills` bucket with a compound key. The recommendation is a new `resources` bucket for clarity and compatibility.
- Whether future changes should extract `weave-architect` and `weave-knowledge` templates using the same pattern.
