# Session Capture: Architecture - 2026-06-07

## Summary

Captured the architecture discussion for `/weave-execute` v1. The design keeps v1 agent-first and skill-only: `/weave-execute` is a bundled skill and slash command wrapper that reuses the existing deterministic `weave task prepare` command before implementation, then lets the agent implement, verify, and update local `tasks.md` evidence directly.

The architecture intentionally avoids adding `weave task execute`, a narrow task-update CLI, or a separate execution run-history artifact in v1.

## Decisions Made

- Ship `/weave-execute` as a bundled agent skill and opencode wrapper only.
- Do not add `weave task execute` in v1.
- Do not add a task status/evidence update helper CLI or helper library in v1.
- Reuse `weave task prepare ... --json` as the deterministic branch-readiness gate before implementation.
- Keep implementation, dependency reasoning, HITL pauses, verification, and `tasks.md` patching in the skill workflow.
- Store durable execution evidence only inside affected `tasks.md` task entries: active index status, task detail `Status:`, checked acceptance criteria, and task-level verification notes.
- Package `/weave-execute` using the same template/install/test path as `/weave-prepare`.

## Options Considered

- Add a deterministic `weave task execute` CLI. Rejected because arbitrary implementation is agent behavior, not deterministic CLI behavior.
- Add a narrow task-update helper CLI. Rejected for v1 to keep the architecture smaller and aligned with the product decision that execution is skill-first.
- Add a shared task artifact update library without a CLI. Rejected for v1; can be revisited if direct markdown patching proves brittle.
- Split architecture facets immediately. Deferred; `architecture/index.md` is sufficient for v1 unless implementation reveals a larger task-artifact editing concern.

## Rejected Approaches

- Duplicating prepare branch logic inside the execute skill.
- Writing execution history into `status.yml`.
- Creating a separate execution run log artifact.
- Allowing `/weave-execute` to commit, push, open PRs, stash, discard, or publish externally.

## User Preferences

- Keep v1 `/weave-execute` skill-direct for `tasks.md` updates.
- Keep the workflow local-only and agent-first.
- Continue independent tasks after failures while skipping dependency-blocked downstream work.
- Include HITL tasks in `all`, but pause before each HITL task for required user input.

## Agent Recommendations

- Add `templates/skills/weave-execute/SKILL.md`.
- Add `templates/opencode/commands/weave-execute.md`.
- Add checked-in installed copies if this repo continues to track generated agent artifacts.

- Update product knowledge after implementation under a new `weave-execute` feature knowledge page.
- Keep task artifact update instructions explicit and conservative: only patch selected task rows, task `Status:`, satisfied acceptance criteria, and task-local verification notes.

## Unresolved Points

None currently blocking architecture. Future work may add a deterministic task artifact update helper if skill-direct patching becomes noisy or brittle.
