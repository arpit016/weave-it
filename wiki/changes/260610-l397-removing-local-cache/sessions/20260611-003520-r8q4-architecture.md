# Session Capture: Architecture - 2026-06-11

## Summary

Captured the first architecture design for removing hidden local routing state from Weave. The architecture replaces session-backed active-change lookup with branch-derived resolution, removes persisted artifact-lane routing and the `weave artifact current` command surface, updates skill contracts to require explicit capture targets, and treats old local session fields as legacy data that remains on disk but is ignored for routing.

## Decisions Made

- Active change resolution should be owned by the resolved Weave root branch, not by `current_change` in the local session file.
- `weave change new` should not be allowed in a non-git root because branch-derived active change cannot be activated there.
- Current/status JSON should expose a stable resolution state such as `branch_active`, `no_active_change`, `invalid_active_branch`, or `non_git_no_active_change`.
- `weave artifact current`, `weave artifact current set`, and `weave artifact current clear` should be removed from the CLI.
- `current_artifact` should not be read by `weave-capture`, `weave-next`, or design-discussion skills.
- Existing local session files may keep `current_change` and `current_artifact` fields, but routing code should not read or mutate those fields.
- Staleness remains source-aware and durable in `status.yml`; this architecture does not change the lifecycle propagation model.

## Options Considered

- Minimal branch-derived resolver while leaving legacy session types in place for safe parsing.
- Full removal of session current-change/current-artifact types and helpers in the first implementation.
- Keeping `weave artifact current` as a deprecated compatibility shim.
- Allowing non-git `weave change new` while reporting that no active change can be resolved afterward.

## Rejected Approaches

- Falling back from branch state to `current_change` when the branch is not a `change/<id>` branch.
- Saving inferred branch-derived active changes back into the session.
- Preserving `weave artifact current` as a warning-only command.
- Allowing non-git change creation for this workflow model.

## User Preferences

- Prefer visible branch-derived active change over hidden local session state.
- Prefer explicit capture targets over inferred or persisted artifact lanes.
- Prefer leaving old local session files untouched.
- Prefer a detailed implementation plan that names exact files and test changes.

## Agent Recommendations

- Implement active-change resolution first, because it is the central seam used by progress, knowledge, task prepare, and slice rollup.
- Remove the artifact command surface and update skill contracts in the same change so agents stop using removed commands.
- Keep the first implementation small by leaving legacy session field types readable but unused.
- Add regression tests for stale session data being ignored before removing unused helpers.
