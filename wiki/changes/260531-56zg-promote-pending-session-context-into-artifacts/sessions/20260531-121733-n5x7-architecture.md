# Session Capture: Architecture - 2026-05-31

## Summary

Generated the initial architecture direction for pending session promotion into artifacts.

The design keeps capture promotion mostly skill-driven, updates deterministic artifact frontmatter generation to ISO timestamps, adds session note metadata guidance, and explicitly leaves downstream pending-session scans out of v1.

## Decisions Made

- Keep capture agent-owned in v1; do not add a compiled `weave capture` command.
- Change generated artifact frontmatter timestamps to UTC ISO via `Date.toISOString()`.
- Keep session filenames as `YYYYMMDD-HHMMSS-<4-char-id>-<artifact>.md`.
- Add session note frontmatter with `artifact`, `capture_mode`, and ISO `captured_at`.
- Use `capture_mode: session-only` for session-only captures and `capture_mode: artifact` for regular artifact captures.
- Bare `weave-capture` should promote pending lane session context into live artifacts.
- Downstream lane skills and `weave-next` should not scan for pending session context in v1.

## Options Considered

- Compiled capture command: rejected because conversational synthesis remains agent-owned.
- Per-session promotion status: rejected because timestamp cutoffs avoid mutating historical notes.
- Raw ISO timestamps in filenames: rejected in favor of filesystem-safe filenames plus ISO frontmatter.
- Downstream hard stops: rejected for v1 because of token cost and workflow friction.

## Rejected Approaches

- Do not add a new CLI capture command in v1.
- Do not add per-session promoted/pending status fields.
- Do not add pending-session scans to `weave-prd`, `weave-architect`, `weave-issues`, or `weave-next`.
- Do not migrate legacy artifact or session files.

## User Preferences

- The user wants pending-session promotion handled when bare `weave-capture` runs.
- The user does not want every downstream lane to audit previous-lane sessions.
- The user prefers ISO metadata for reliable timestamp comparison.

## Agent Recommendations

- Update `artifactFrontmatter(...)` to emit ISO timestamps.
- Update canonical skill templates and installed copies together.
- Keep behavior backward-compatible for existing date-only artifacts and legacy session notes.
- Validate the behavior through skill text assertions and frontmatter generation tests.
