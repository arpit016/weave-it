# Session Capture: Architecture - 2026-07-21

## Summary

Architecture dissection for the fix-init change (260721-6d48-fix-init). The change demotes the machine-local session (`~/.cache/weave/current-session.yml`) to an optional, lazily-created cache, makes `weave init` a safe no-op when a valid `.weave/workspace.yml` already exists in the tree, and renames the `no_session` JSON status to `not_initialized` so the name reflects the genuine uninitialized case. The committed `.weave/workspace.yml` plus cwd plus the git branch become the sole source of truth for initialization and command context.

## Decisions Made

- **D1 — `weave init` top-of-function short-circuit.** At the very top of `initWorkspace()` in `src/lib/init-workspace.ts`, before the `shouldReplaceSession` prompt and before `selectInitMode`, call `findWorkspaceMode(cwd)`. If it returns a valid workspace, return a new `already_initialized` status immediately with the message: `Weave is already initialized (mode: <repo|workspace>). Start a new change with \`weave change new "<title>"\`.` No scaffold, no `git init`, no repo move, no session write. This makes the destructive `initWorkspaceFromGitRepo` adoption path syntactically unreachable for any already-initialized tree. Add `already_initialized` to `InitStatus`.
- **D2 — Repo-mode `weave workspace` is derive-only.** In `src/lib/show-workspace.ts`, `buildRepoModeResult` no longer errors when the session is absent. When `findWorkspaceMode(cwd)` returned a valid repo-mode workspace but no session exists, derive a single folder from the workspace root (`workspacePath`) with `id`/`name` from the dir basename or `workspace.yml.name`, `kind: "app"`, and return `status: "ok"`, exit 0. Do NOT write a session file. This preserves the documented read-only contract of `weave workspace`. When a session exists, behavior is unchanged.
- **D3 — Rename `no_session` -> `not_initialized`.** Rename across `AddFolderStatus` and `ShowWorkspaceResult.status` types, the return sites, the command-wrapper exit-code checks in `src/commands/add.ts` and `src/commands/workspace.ts`, the tests in `tests/init.test.ts` (lines 268 and 432), and the core-command-reference behavior doc. The renamed status is emitted only in the genuine uninitialized case (no `workspace.yml` anywhere up the tree, no session). No in-repo JSON consumer branches on the `no_session` string, so the rename is safe internally.
- **D4 — `weave add` repo-mode lazy session (target only).** Restructure `addFolder` in `src/lib/add-folder.ts` to call `findWorkspaceMode(cwd)` first. If undefined, return `not_initialized`. If workspace mode, call `addFolderToWorkspace` (unchanged, session-free). If repo mode, load the session; if absent, lazily create one via a new `loadOrCreateSession(folder, now, sessionPath)` helper in `src/lib/session-state.ts` containing ONLY the target folder, then proceed with `addFolderToRepoSession`. The workspace-root repo is not auto-added.
- **D5 — `weave change *` and `weave doctor` unchanged.** `resolveChangeContext` in `src/lib/workspace-mode.ts` already works from `workspace.yml` + branch and only errors when it is genuinely missing. `weave doctor` already gates on `findWorkspaceMode`. No changes needed.

## Options Considered

- **D1 alternatives:** (a) per-mode checks inside `initRepoMode`/`initWorkspaceMode` — rejected because the guard is duplicated and the session-replace prompt still runs first; (b) top short-circuit plus a defensive assertion inside `initWorkspaceFromGitRepo` — rejected as belt-and-suspenders; the walk-up short-circuit alone is sufficient since the destructive path becomes syntactically unreachable.
- **D2 alternatives:** (a) lazily write a session file on `weave workspace` — rejected because it breaks the documented read-only contract; (b) derive by default with a `--attach` opt-in flag — rejected as over-engineered for V1.
- **D3 alternatives:** (a) keep the `no_session` name and change only its semantics — rejected because the name becomes a mild lie; (b) emit `not_initialized` plus a deprecated `no_session: true` boolean alias — rejected as unnecessary churn since no in-repo consumer branches on the string.
- **D4 alternatives:** (a) lazy session contains the workspace-root repo AND the target (matching `weave init && weave add`) — rejected; `weave add` semantics are "add the named folder, nothing more", and the workspace root is always derivable from `workspace.yml`; (b) target only with a one-line notice — rejected because the PRD already decided lazy session creation is silent.

## Rejected Approaches

- Ripping out the session concept entirely. The PRD Non-Goals keep the session as an optional cache; repo-mode multi-folder scope stays machine-local by design.
- Committing repo-mode folder membership into the repo. Out of scope by PRD.
- Adding a defensive assertion inside `initWorkspaceFromGitRepo` (D1 option b). The top-of-function short-circuit already makes the destructive path unreachable for already-initialized trees.
- Warning on malformed `workspace.yml` during `weave init`. Existing behavior (treat as absent) is preserved for V1; a follow-up could warn. Out of scope.

## User Preferences

- `weave init` on an already-initialized workspace is a pure no-op for files, repo location, and the machine-local session. Lazy session creation happens in everyday commands, not in `weave init`.
- The "already initialized" message includes the detected mode and suggests the next action: start a new change with `weave change new "<title>"`.
- Repo-mode `weave workspace` must remain read-only; it derives display without writing a session file.
- The status rename should be a clean rename to `not_initialized`, not a backward-compat alias.

## Agent Recommendations

- Keep the change minimal and surgical: top-of-function guard in `initWorkspace`, derive-only repo-mode workspace, lazy session only on the `weave add` write path, and a mechanical rename. No new abstractions.
- Update `wiki/knowledge/domains/cli-commands/features/core-command-reference/behavior.md` in the same change so the dispatch table and repo-mode "Next: weave init" hint reflect the new behavior.
- Add tests that simulate a clone (workspace.yml present, isolated/empty session path) for both `weave add` and `weave workspace` in workspace and repo modes, plus an idempotent `weave init` test on an already-initialized tree.
